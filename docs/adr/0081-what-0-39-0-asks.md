# ADR 0081: What guideline 0.39.0 asks

**Status**: accepted (2026-09-29).

## Context

Tadas moves its pin from guideline v0.38.0 to v0.39.0. The release
retells `architecture.md` around a scaffold that runs, and keeps every
rule ID. It renames one type, and every tree follows it: `OpContext` is
`TenantContext`, and its module `om/opcontext.py` is `om/context.py`.
It names five reversals. Four now ask what Tadas already does, and one
lowers a severity. Here is where Tadas stands on each rule the release
changes:

| Rule | What v0.39.0 asks | Here |
|------|-------------------|------|
| CTX-02, TenantContext | The stages are declared in `<pkg>.om.context`, and a stage declared anywhere else under `om` is a finding. `arch-check` takes no alias for the old module. Its section is `## TenantContext`. | Follows with this change. The module and the type take their new names in the code, the tests, the skills, the docs, the CTX-26 sites in `pyproject.toml`, and ADRs 0010 and 0061. ADRs 0067 and 0079 keep the name the release they record used. On the tree before the rename, v0.39.0 gives 3 CTX-02 findings: `RequestContext`, `IdentityContext`, and `OperatorContext`, each declared outside the stage module. |
| OM-03, Naming Entities; NET-24, The Gateway | The edge marker is `IdempotencyRecord`, fenced by its `attempt_id`. The lease runs from the attempt id, a `uuid_v7`, and `finish`, the release, and a rerun's re-mint are conditional on it. v0.38.0 named it `IdempotencyMarker`, with an attempt token. | Follows, as it did. `idempotency/types/record.py` declares `IdempotencyRecord` with `attempt_id`, and the re-mint reads it in its own statement ([ADR 0014](0014-the-re-mint-reads-the-idempotency-marker.md)). |
| OM-06, Naming Entities | An append-only record carries its time in a field of its own, `created_at` or a name such as `produced_at`, and its time is never read out of its id. v0.38.0 took the time from the id and gave the record no column for it. | Follows. `Event` keeps `produced_at`, which [ADR 0015](0015-the-event-keeps-its-produced-at.md) recorded as a deviation. That record is superseded. The other records that are only ever created carry `created_at`. |
| CON-17, Shape of an Operation | The manager's copy stamps a create's times, with the actor and its own fields. Only the id stays as the caller built it. v0.38.0 left the times as constructed. | Follows. A create that takes its entity from the caller stamps the clock over the caller's times: `create_task`, `create_file`, and the work queue's `enqueue`. A caller cannot backdate a row. |
| STO-11, STO-14, Defining ORM Classes | The feed and identity-scoped table mixins are gone. A table whose `org_id` leads a compound index sets `__org_id_index__ = False`, and an identity table declares the column its scope map names. | Follows, as it did. `IdentifiableMixin` reads `__org_id_index__`, and the events, billing accounts, and billing deliveries tables set it to `False`. No table is identity-scoped yet, and `storage/scopes.py` declares the column such a table's policy reads. |
| DEL-14, Views, View-Models, Models | Its severity drops from medium to low. | Follows. Each portal feature keeps a model module, a view-model hook, and its views. |
| DEL-15, API Access; NET-15, Clients Live in One Place | The TypeScript client lives in `clients/typescript/`, beside the Python one, and every browser app imports it. | Follows, in its own pull request (#171). |
| OPS-11, Operational Skills | The operational skills live in `.agents/skills/`, and `.claude/skills` links to it. Each skill names its files by a path from its own folder. OPS-11 finds a built-in skill in either folder. | Follows, in its own pull request (#170). |

The rest of the release is the guideline's own: `architecture.md` at a
third of its length, with every `##` and `###` title kept, the renamed one
aside; `scaffold/acme_root/` and `scaffold/new.py`, which a new system
starts from; a `**Shape.**` line in the lenses; the skills on the Agent
Skills standard; and the gates that hold them. Tadas started before the
scaffold and copies none of it.

`make check` runs `arch-check` at v0.39.0, and it passes: 106 rules over
352 files, no finding, and 7 accepted by an exception. The same five
entries of `[[tool.arch-check.exception]]` accept them as at v0.38.0.

## Decision

**The name follows the guideline in every text that describes code in
force.** A rename that stops at the code leaves a reader of a doc or a
skill with a name no file declares. The code, the tests, the skills, the
docs, `pyproject.toml`, and ADRs 0010 and 0061 say `TenantContext` and
`om/context.py`. An ADR that records a release keeps the name that
release used.

**The rename moves no part of the wall between tenants.** Read the
new names as the old ones, and every line the rename touches reads as
it did, formatting aside. No field, check, permission, or transition of
the tenant stage changes. The test that lists every site that constructs
a stage lists the same sites under the new names.

**No alias.** The checker takes none, and a second name for the stage
would keep the old one alive. Nothing imports the old module.

**ADR 0015 is superseded.** Its decision, `Event` keeps `produced_at`, is
the rule now, and the route out it named is not taken. Its row in the
deviations table says so.

**Nothing of v0.39.0 is a deviation.**

## Consequences

- A new stage or a new transition's helper goes in `om/context.py`, and
  a tenant operation takes `TenantContext`.
- A new record that is only ever created carries `created_at` or a time
  of its own, and nothing reads a record's time out of its id.
- A new create that takes an entity from its caller stamps the times in
  the manager's copy.
